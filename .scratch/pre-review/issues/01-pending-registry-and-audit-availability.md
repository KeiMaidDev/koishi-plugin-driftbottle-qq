# 01: 待审区注册表模块与预审触发判定

**What to build:** 为预审功能打下地基：新增待审投稿注册表——用独立的 LocalStorage 存储命名空间（与瓶子数据、历史记录平级）存放待审投稿，活过机器人重启；提供提交、通过、驳回、撤回操作；待审编号全局递增、持久化、永不复用。同时提供「自动内容安全审核实际不可用」的纯判定函数（与现有自动审核的放行条件互为补集：配置关闭，或开启但凭证缺失，均判为不可用）。本票据不含任何指令或界面接线，测试即可验证。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 提交待审投稿后获得新的待审编号；驳回/撤回后该编号作废，后续提交不复用已用编号
- [ ] 通过操作返回供转正落库所需的完整投稿数据（含文本、标题、媒体路径、作者、推送偏好），并使该投稿离开待审区
- [ ] 驳回与撤回均删除投稿记录及已下载的媒体文件；撤回一份不存在或已处理的投稿返回明确的失败结果
- [ ] 用同一份存储重建注册表（模拟重启）后，编号计数延续、待审列表完整
- [ ] 触发判定函数真值表正确：isExamine 关闭→不可用；开启但缺 Appid/key→不可用；开启且凭证齐全→可用
- [ ] 假 LocalStorage 注入方式与现有举报注册表测试一致；测试覆盖上述全部行为
