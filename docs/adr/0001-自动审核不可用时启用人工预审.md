# 自动审核不可用时启用人工预审

Status: accepted

## 背景

插件原本的行为：`isExamine` 关闭时，扔瓶内容不做任何检查、创建即入海（`show: true`）。腾讯云自动审核（`delSetu`）的实际放行条件是 `isExamine && Appid && key`——配置开启但密钥缺失时，内容同样无人把关。

## 决策

当自动内容安全审核**实际不可用**（`isExamine` 为 false，或开启但 Appid/key 缺失）时，本地「扔漂流瓶」的内容进入独立的待审区存储，由管理员**预审**：通过后才转正为瓶子入海，驳回则丢弃投稿及其媒体文件。`adminQQ` 用户扔瓶跳过预审。

依据：关闭自动审核不应等于完全无人把关；以"实际可用性"而非配置字面值作为触发条件，使自动/人工两条路径对"内容是否经过把关"的判定保持一致。

## 边界（明确的"不"）

- 待审投稿不是瓶子：不占瓶子 ID（通过时才分配）、不入海、捞不到、不计入海里统计。
- 待审区使用独立存储，**批量上传云漂流瓶时不上传待审区内容**。
- 留言、云瓶（扔向远端服务器的内容）不在预审范围内。
- 待审投稿**无自动过期**：驳回是删除媒体文件的破坏性操作，不做自动化，堆积由管理员手动消化。

## Considered Options

- 仅按 `isExamine` 字面值判定触发（被否）：密钥缺失时内容实际无人把关，兜底失效。
- 待审投稿先入瓶子库、`show: false` 等审（被否）：占瓶子 ID 产生空洞，与"驳回不产生瓶子"的语义冲突，且会混入海里统计与云瓶上传。

## Consequences

- 扔瓶从"即时入海"变为"等待预审"，属默认行为变更；依赖旧行为的用户需知晓。
- 管理员长期不处理会导致待审区堆积；控制台面板展示待审数量以暴露该情况。
